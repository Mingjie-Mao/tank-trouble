# P29：机会寻敌与纪律开火八问审计

日期：2026-07-23

## 实现

P29 从 P28 的 656 维移动策略扩为 667 维，新增：

- 可信炮线、到射击位进度、来弹风险和机会方向 5 维；
- ready line、武器可用、扳机释放、真实预测命中、自杀弹道和压力弹质量 6 维。

旧 656 列和动作头原样热启动，新增列置零，初始网络输出误差为 `0.0`。18 个
旧分数被解释为 9 路移动分布和条件开火分布。只有真实预测命中或足够近的压力
弹、且 ready line 足够、武器与扳机可用、不是自杀弹道时才允许开火；预测必中
直接强制单发。

Reward 使用机会势能差、真实开火事件和真实命中事件。纯跑图成功不进入攻击
缓存；只有实际命中轨迹会保留机会推进/命中前窗口。最终稳定性探针冻结 P28 的
旧主干与动作头，只允许新增 11 维对应的首层列学习，critic 从 actor 特征 detach。

## 八问结果

1. **目标：黄色。** Reward 已表达“形成安全机会、及时单发、真实命中、避免
   自杀弹道”，但仍是 12 秒生存课程，不等同于原版观赏性胜利。
2. **信息：绿色。** 所有机会 reward 和开火门依赖的状态都进入 667 维观测；
   没有 P26 的隐藏永久访问状态问题。
3. **表示：黄色。** 条件开火分布能表达移动与独立开火，严格门能表达纪律；
   但当前机会方向是瞬时分析，没有长期锁定某个击杀计划。
4. **经验：红色。** P25v2 教师在一组 3 图里产生 1 条命中，但正式 16 图启动
   为 0 条命中。PPO 缓存主要来自随机采样命中，确定性寻敌关键数据仍不足。
5. **学习信号：黄色。** 机会势能差和实际命中给出正确方向，失败局也保留命中
   `+2`；但真正开火机会仍稀少，BC 很难从随机命中窗口恢复完整寻敌路线。
6. **优化：红色。** 普通 PPO 在 iter02 达到固定局 1 枪1中，iter03/04 退化；
   只训练新增特征后 iter02 仍达到 1枪1中，iter03 又退化。小 KL 不能防止 argmax
   边界翻转，当前训练不能稳定停留在好策略。
7. **泛化：红色。** P29c iter02 的 5 图确定性面板为 0/5 命中，访问 1–4 格；
   一图打 5 发压力弹但没有命中。固定训练探针的成功不泛化。
8. **评价与最优性：红色。** 当前只证明严格门能消除明显乱射，并在特定图实现
   1枪1中；不能证明寻敌能力。现有 P25 教师本身也无法稳定提供课程上界，所以
   尚不能讨论接近最优。

## 探针数据

- 宽松 P29：训练 waste 约 25–31%，拒收。
- 严格 P29b：waste 降为 0%，iter01 固定局 1枪1中；iter02 PPO 后退化。
- 特征冻结 P29c：iter02 保持 1枪1中；iter03 再次退化。
- 教师启动 P29d：16 局 0 条教师命中；后续随机命中缓存增至 1,294 步，但
  确定性策略仍不命中。

## 当前判决

严格 fire gate 可以保留，已经解决“无意义乱射”。P29 不能升为寻敌模型。下一
步不应继续 PPO，而应先构造能够稳定输出“移动到射击位→转向→单发命中”的击杀
计划老师，或把课程拆成可独立成功的射击位导航、瞄准、开火三段，再聚合训练。

局部有效的人工 review 快照：

```bash
python3 training/watch.py --policy p29-opportunity-survival \
  --net training/models/p29c_feature_only_actor_iter02.pt --seed 664415901
```
