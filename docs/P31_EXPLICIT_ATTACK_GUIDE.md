# P31：显式跑图、瞄准与击杀老师

日期：2026-07-23

## P30 为什么没有表现出主动进攻

人工 review 的判断正确。对回放种子 `30000001` 做逐决策诊断后：

- 共 102 次决策，P30 有 76 次选择原地不动；
- 55 次存在明确可提高机会的候选移动，P30 只选中 2 次；
- 只访问 2 格，0 枪、0 命中，最终分数流干。

因此失败点不是没有计算出方向。9 路反事实分析已经多次指出正确动作，但 P30 把它们
仅作为普通输入，期待稀疏 PPO 自动学会“第 i 个预演对应第 i 个动作头”。同时训练又
冻结了旧动作头和大部分主干，新增输入只能间接扰动旧策略。结果是奖励盆地存在，动作
选择却没有通往盆地的可靠入口。

## P31 的处理

P31 暂时停止继续训练错误学生，直接使用已经验证过的 360° 机会 MPC 作为显式老师。
老师对 18 个移动/转向/开火动作分别做 24 帧原版物理前推，并统一评价：

- 到射击位和可信炮线的机会势能变化；
- 炮口朝最佳反弹或直射炮线的对准过程；
- 真实开火、压力弹和命中；
- 来弹风险、死亡和明显自杀弹道；
- Laika 使用新鲜状态和独立随机数，不读取对手内部状态。

这不是最终部署模型，而是下一轮动作监督和 DAgger 的数据源。先确认老师行为符合人的
目标，再蒸馏，避免继续用错误动作分布训练。

## 单图探针

原版规则，地图种子 `30000001`，规划器种子 `0`，前推 24 帧、首动作保持 8 帧：

- 真结果：胜利；
- 主动移动：17.79 格；
- 开火：14 枪；
- 击杀：1 次直接击杀；
- 自身死亡：无。

同一地图上的 P30 是 0 枪、0 命中、分数流干，因此 P31 已经修复“没有任何跑图和
瞄准指导”的老师层问题。跨地图稳定性和学生可蒸馏性尚未验证。

## 回放

优先看原版规则：

```bash
python3 training/watch.py --policy p31-guide-original --seed 30000001
```

查看生存经济下的行为：

```bash
python3 training/watch.py --policy p31-guide-survival --seed 30000001
```

该老师每次决策需要运行短期物理搜索，回放可能比普通网络慢。人工 review 重点是：是否
持续向射击位推进、发现炮线后是否有明显转向校准、开火是否对应真实击杀尝试，以及
风险规避是否破坏进攻连贯性。通过后再采集老师状态—动作对并蒸馏为实时学生。
