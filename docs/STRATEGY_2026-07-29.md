## Main Problems And Strategies

### 1. Search teacher is strong, but pure network loses information

Problem: MPC can look ahead; the network only sees one state. Early distillation
failed because the observation did not answer action-conditional questions like
"which movement avoids the bullet."

Strategy:

- Keep score regression over all 18 actions.
- Keep 408-dim physical observation as the stable base.
- Add only factual features, not hidden value labels.
- Any new branch should include action-conditional features if the label asks
  action-conditional questions.

### 2. P22 got strong but remains reactive

Problem: P22 is now strong, but it is still mostly a distilled search policy with
a short 48-frame teacher horizon. It wins well, but does not explicitly optimize
for creating future shot opportunities.

Strategy:

- Treat P22 as the confirmed baseline and bootstrap distribution.
- Do not keep running blind P22 DAgger unless there is a new diagnostic reason.
- Use P22 to generate on-policy states for new teachers.

### 3. Reward/curriculum teachers do not transfer automatically

Problem: P24 showed that a teacher can look good under a curriculum, while the
student still fails on original rules.

Strategy:

- Every curriculum branch must have original-rule validation.
- Do not promote based on curriculum score.
- Keep original-rule gates: quick 80/200 games for signal, then 1000 + second seed
  for promotion.

### 4. Learned value leaf was unsafe

Problem: P23 learned state values from policy-generated games and leaked maze/state
correlations. It made the teacher worse and more passive.

Strategy:

- Do not reintroduce value leaf without per-episode split and iterative policy
  improvement.
- Prefer teacher objectives that directly score candidate actions by original-rule
  consequences and opportunity facts.

### 5. P25v2 is champion, but fire control is still the next bottleneck

Problem: P25v2 best is officially stronger than P22, but the logs show a clear
fire-control failure mode. Iter01 was best at 2.0 shots/game and 19.8% hit rate.
Iter02 fired 2.7 shots/game, hit only 14.2%, and fell from 76.2% to 73.8%.
The champion's official eval also fires more than P22, so further gains likely
depend on making opportunity shooting more selective rather than simply adding
more DAgger.

Strategy:

- Keep `p25v2_opportunity_best.pt` frozen as champion.
- Do not overwrite P25v2 best during fire-gate experiments.
- Build P25v3 as a separate experimental branch.
- Compare not just win rate, but double death, loss rate, shots/game, hit rate,
  and average game length.
- Prefer a P22-anchored fire gate: P22 supplies stable state coverage; the
  opportunity teacher should override only when the line quality is strong.

### Step 2: Start P25v3-firegate as a separate challenger

Goal: preserve P25v2's opportunity gains while preventing the iter02 over-fire
regression.

First implementation should avoid changing the 440-dim observation or v2 data
schema. The lowest-risk approach is a post-network fire gate:

- Score all 18 actions as before.
- Let the network choose movement from fire and non-fire variants.
- Permit fire only when the predicted fire action beats the paired no-fire action
  by a margin.
- Sweep the margin on existing `p25v2_opportunity_best.pt` before retraining.

Suggested sweep:

```bash
python3 training/opportunity_distill_v3.py gate-sweep \
  --net training/models/p25v2_opportunity_best.pt \
  --n 200 \
  --seed 973000 \
  --workers 8 \
  --margins 0 0.02 0.05 0.08 0.12 0.16
```

Decision:

- If a margin improves win rate or holds win rate while reducing double death,
  run `1000@970000` and `500@990000` for that gate.
- If every gate loses win rate, do not use post-gating; move to data weighting
  or a trained fire-head.

### Step 3: If post-gating fails, diagnose opportunity behavior

Measure:

- fire rate compared with teacher
- hit rate
- direct-vs-rebound kill composition
- double-death after own kill
- lethal misclassification rate on P25v2 on-policy states
- regret distribution under the P25v2 teacher

Likely fixes:

- Increase DAgger data size before changing architecture.
- Add a fire gate loss or separate fire head.
- Keep opportunity data in `training/opportunity_data_v2/`; do not mix v1 and v2.
- Consider more bootstrap from the new stronger P22 because the old P25v2 design
  was planned around a weaker ~68% P22.
