# P36：三秒指数连吃金币

## 规则

- 所有可达格子的金币基础值统一为 1。
- 双方各自维护公开的连吃层数和 3 秒（75 帧）倒计时。
- 无连吃时第一枚金币收入为 1，并启动 3 秒倒计时。
- 倒计时内吃到下一枚时，本枚收入为 `2^当前层数`，随后层数加一并刷新 3 秒。
- 超时后层数归零，下一枚重新从 1 开始。
- 撞墙不扣经济，也不产生额外 reward penalty。
- 主动安全击杀终局奖励高于 Laika 自伤死亡；两者均非负收益。

模型观测新增双方的连吃层数和剩余时间。导航目标仍选择当前性价比最高的剩余金币，
但模型看到的是通往目标的下一个合法 waypoint，而不是隔墙直指最终金币。

## 机制验证

- 单元序列：连续三枚结算为 `1 + 2 + 4 = 7`。
- 75 帧超时后下一枚恢复为 1。
- 新观测维度为 801；旧 797 维 waypoint 模型迁移的输出误差为 0。

Laika 64 图、30 秒、原版战斗基线：

- 单体最终经济：均值 158.41，中位 25，P75 41.5，最大 4095；
- 最大连吃层数：均值 3.73，P75 5，最大 12；
- 每局实际领取金币数（双方合计）均值 8.45；
- 碰墙经济扣分为 0。

该结果证明三秒连吃在真实地图运动中可达，但指数尾部会造成极高方差。

## 八问审计（启动阶段）

1. **目标：黄色。** 连吃明确奖励持续移动和快速选择下一目标，能够建立启动跑图盆地；
   但所有金币等值时，最优局部行为可能是清理身边金币而不是朝对手索敌。高层连吃还可能
   压倒击杀价值，因此尚未证明形成索敌盆地。
2. **信息：绿色。** 模型看到剩余金币图、双方经济、双方连吃层数、双方剩余时间、
   当前 waypoint 的局部方向、路径距离和有效位。reward 使用的启动状态没有隐藏。
3. **表示：黄色。** 18 个联合动作和逐 waypoint 方向足以表达转向、前进与开火；公开
   倒计时使前馈策略不必自己记忆连吃历史。但模型仍无动作承诺，可能在拐角逐帧摇摆。
4. **经验：红色待建。** 旧 797 维 replay 与新 801 维观测不兼容，不应复用。当前只有
   Laika 基线，没有新规则下的模型成功轨迹或连吃导航 replay。
5. **学习信号：绿色偏黄。** `1,2,4,8...` 是即时、不可往返刷取的真实事件奖励，
   waypoint 势能提供两枚金币之间的密集 credit。但指数回报方差很大，稀有长连吃可能
   主导 PPO advantage，后续需监控回报裁剪和层数分布。
6. **优化：黄色。** 新输入已经显式加入，但对应权重从零开始。应先冻结旧主策略，训练
   coin adapter，并只保留真实路径进展/吃币片段；不能用旧的整局偶然击杀 replay。
7. **泛化：红色待测。** 64 图 Laika 基线从 0 到 4095，说明地图和轨迹方差巨大。
   训练后必须在独立种子带报告连吃层数分布，而不能只看平均经济。
8. **评价与最优性：红色待测。** 当前只证明机制可进入。尚未验证纯网络能否稳定启动，
   也未证明连续采币自然转化为接敌和主动击杀。

## 当前判决

启动阶段可以进入短训练：使用全新 801 维 replay、冻结旧 P29c 主策略，只训练金币输入
适配和 value head。首个门槛只检查开局 3 秒内是否稳定离开出生格、是否续上第二枚金币、
是否减少原地转向；索敌和最终击杀在启动行为稳定后再审计。
