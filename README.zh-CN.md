# Tank Trouble AI

这是一个忠实移植原版 Flash **Tank Trouble** 的 Python 项目，以及一个结合学习、
规划、安全验证和严格评测、可直接落地的浏览器 AI。

## 体验当前冠军

**[在浏览器打开 Tactical vs Laika](https://tank-trouble-ai.pages.dev/)**

不需要登录或安装。网页支持：

- Tactical 以原版 25 FPS 对战 Laika；
- 人类对 AI、AI 对 AI；
- 固定迷宫种子、换图和清零比分；
- 实时搜索率和 p95 延迟监控；
- 冻结的四对手晋级报告。

当前部署冠军是 **Tactical Smooth**。它主要是浏览器原生在线搜索智能体，不是历史上
的 P27b 神经网络。它用精确世界模型评估合法动作，再叠加可见子弹安全验证、击杀后
生存、拓扑追击和物理验证的移动目标反弹截击。

Smooth 在冻结的 Tactical 冠军之上加了两样东西：**墙面接触物理**，几乎消除了贴墙
磨蹭；以及**开火续走**，把一枪和开完这枪之后的移动放在一起打分，而不再假设坦克
开完枪就站着不动。两者都来自上游 KillField，但都是在消融实验查清各自到底贡献了
什么之后才采纳的 —— 见
[消融报告](docs/KILLFIELD_UPSTREAM_ABLATION_2026-08-16.md)。

## 当前成绩

| 智能体 / 基准 | 真结果 | 决策成本 | 定位 |
|---|---:|---:|---|
| **Tactical Smooth vs Laika** | **1912/2000 = 95.6%** | **p50 0.66 ms / p95 20.05 ms** | 部署冠军，全新留出集 |
| Tactical Smooth 四对手池 | 302/320 = 94.4% | 红黑换边，配对 | Laika、Hunter、Dodger、Random |
| Tactical（冻结前任）vs Laika | 576/600 = 96.0% | p50 0.75 ms / p95 12.57 ms | 前任冠军，同协议 |
| KillField vs Laika | 262/300 = 87.3% | 参考 p95 5.92 ms | 第三方基线，2026-08-12 快照 |
| KillField 四对手样本 | 76/104 = 73.1% | 相同种子协议 | 第三方泛化基线 |
| P27b | 1330/1500 = 88.7% | 8.6 ms | 历史纯网络基线 |
| 精确状态安全 MPC | 297/300 = 99.0% | 秒级 | 特权离线老师，不可部署 |

上表的决策成本均为 Node 下的独立测量。用来对照的 40 ms 是**浏览器**帧预算，两者
尚未做过交叉标定；线上页面自身的遥测对前任冠军报出过明显更高的 p95。因此这些数字
应视为候选之间的横向比较，而不是浏览器实测值。

KillField 两行描述的是**仓库内 2026-08-12 快照**在本项目种子上的成绩。上游此后
继续更新，其当前版本自报 897/1000 = 89.7%；这个数字在消融实验中被逐项精确复现。
两个数字来自不同的种子基和不同的物理，互相都不是对方的效应量。

Smooth 的晋级依据是**事前注册的非劣效检验**，不是更好的点估计。界值、终点和判定
表在留出实验开跑之前就写死了，用的是从未参与过任何调参决策的种子基：

| | 冻结 Tactical | Tactical Smooth |
|---|---:|---:|
| 真胜（2000 局配对） | 1914（95.70%） | 1912（95.60%） |
| 双亡 | 29 | **22** |
| 贴墙帧占比 | 21.35% | **3.00%** |
| 下了移动指令却零位移 | 12.52% | **0.12%** |
| 每秒方向切换 | 7.23 | **3.60** |
| p50 / p95 | 0.75 / 12.57 ms | 0.66 / 20.05 ms |

```
差值      -0.10pp    95% CI [-1.34pp, +1.14pp]
McNemar   81 害 / 79 救, p = 0.937
事前界值 -1.5pp -> CI 下界越过界值 -> 非劣成立
```

也就是说，Smooth 拿到了走位质量，而胜率上没有可测量的代价：2000 局里差 2 场，
被害和被救的局数几乎完全对称。这里不会把"不显著"写成"一样"——界值事先固定，
正是为了让这个结论有明确含义。

前任冠军的合并成绩继续保留作对照，它遵循的是同一套纪律：

| 盲测种子基 | 真胜 | 负 | 双亡 | 平 | 胜率 |
|---|---:|---:|---:|---:|---:|
| `2900000` | 291 | 5 | 4 | 0 | 97.0% |
| `3200000` | 285 | 10 | 5 | 0 | 95.0% |
| **合并** | **576** | **15** | **9** | **0** | **96.0%** |

两次都是同一个冻结策略在全新种子上的 300 局。两者相差 2 个百分点，这恰好量出
单个 300 局种子基本身能有多大摆动——这正是"换冠军需第二种子基复验"这条规则
存在的理由，也是这里公布合并值而不是最好值的理由。冻结前代在 `2900000`
种子上是 288/300。原版 25 FPS 每帧预算是 40 ms，因此最差 p95 16.19 ms 仍足够实时。

所有对外成绩都使用**真胜率**。先击杀 Laika、随后被仍在飞行的子弹打死，算双亡，
不算胜利。

## 完整技术路径

项目并不是直接转向搜索，而是先确定学习能解决什么、在哪里失效，以及规划提供了
什么额外信息。

| 阶段 | 最好结果 | 得到的结论 |
|---|---:|---|
| Random / 手写 Hunter | 0.5% / 22.5% | 难度参照 |
| P17 无模型路线（BC + PPO） | 36.4% | 子弹预测和导航比奖励塑形更重要 |
| 无泄漏 MPC | 96.0% | 这个游戏非常奖励短期精确规划 |
| P21–P27 搜索蒸馏 | 最高 88.7% | 应回归全部动作分数；argmax 克隆受并列标签影响 |
| P27b 纯网络 | 88.7% | 快速学习基线，但弱于公平在线规划 |
| Tactical | 96.0% | 搜索 + 显式安全 + 失败驱动反规避是落地主线 |
| **Tactical Smooth** | **95.6%** | 走位质量与策略强度是两个独立维度；物理修好了前者，且没有折损后者 |
| 特权精确老师 | 99.0% | 可作标签 oracle，但读取隐藏 RNG/对手状态 |

### Tactical 决策栈

```text
可见游戏状态
      ↓
逆密度攻击场
      ↓
10 个合法第一步动作 × 精确模拟 36 帧
      ↓
可见子弹和己方子弹安全验证
      ↓
稀疏两段式纠正 / 击杀后生存
      ↓
拓扑反卡死追击 + 移动目标反弹截击
      ↓
按原版 25 FPS 输出动作
```

公开冠军没有启用学习门控。第一版 MLP 动作先验在离线 Top-7 验证中覆盖了
99.17% 的老师动作，但实战仍平均搜索 8.74/10 个动作，p95 也没有下降。因此它
被拒绝，没有静默替换 Tactical。

## 自博弈与模型改进

网页的 **AI 对 AI** 模式让两个独立智能体在同一个精确物理世界中对战；右侧 AI
接收镜像后的可见状态。它是实时演示和诊断工具，浏览器中的对局**不会**训练或
修改线上冠军。

真正的改进在离线受控飞轮中完成：

```text
冻结 Tactical 与候选使用相同种子、红黑换边
      ↓
Laika / Hunter / Dodger / Random 四对手联赛
      ↓
保存每个修复、退化、双亡、平局和困难种子
      ↓
采集搜索老师纠正，训练下一候选
      ↓
检查胜率、配对退化、双亡、平局、颜色差、p95
      ↓
300 个全新 Laika 种子 → 晋级或淘汰
```

网页展示上一次冻结联赛和实时性能。离线 flywheel 生成机器可读对照报告与困难局
回放集。所有门槛通过以前，候选都不会公开。

项目已设置每天本地时间凌晨 2:00 的可断点无人值守飞轮：先跑永久回归种子，
失败候选立即停止；只有同种子四对手池全部通过，才解锁 300 局盲测。

```bash
cd web

# 用完全相同的局面对比隐藏候选和冻结 Tactical。
npm run flywheel:selfplay -- \
  --candidate p27-js-two-stage \
  --rounds-per-side 10 --seed 2400000
```

## 快速开始

当前冠军直接使用上面的固定网页。原版 Python 移植只需要 Python 3（本地窗口依赖
`tkinter`）：

```bash
python3 play_tank_trouble.py
```

历史 Python 基线仍然保留：

```bash
# 纯网络历史基线，不是当前浏览器冠军
python3 training/watch.py --policy p27b

# 特权慢速老师
python3 training/watch.py --policy exact

# RL 线冠军
python3 training/watch.py --policy model
```

对照反编译原版验证移植：

```bash
python3 test_original_port.py
```

运行 Python 测试套件（用 `unittest`，不依赖 pytest）：

```bash
python3 -m unittest discover -s training -p "test_*.py" -t .
```

本地启动浏览器产品：

```bash
cd web
npm install
npm run dev
```

## 评测规则

1. **先杀不等于赢。** 结算期内仍在飞行的子弹可以打死发射者；报告分别统计胜、
   负、双亡和平局。
2. **候选必须同种子、红黑换边。** 结果变化来自策略，不来自迷宫或出生颜色。
3. **先泛化、后晋级。** 候选先对战 Laika、Hunter、Dodger、Random，再进入最终
   Laika 盲测。
4. **延迟也是门槛。** 只变强不够，p95 必须保持在 40 ms 帧预算以内。
5. **冠军始终冻结。** 训练与自博弈只能产生候选，不能原地修改部署策略。

## 没有走通的方向

| 尝试 | 结果 | 结论 |
|---|---|---|
| P8 后八个奖励塑形版本 | 全部未晋级 | 信息不足才是瓶颈 |
| CNN 地图头 | 22.5% | 四个显式导航特征更有效 |
| PPO 续训 60M 步 | 36% → 21% | 恒定学习率长训最终崩溃 |
| argmax 行为克隆 | 8.9% | 大量动作并列，应学习分数地形 |
| 学习价值叶子 | 老师 93.5% → 87.5% | on-policy 价值目标固化被动行为 |
| 单纯加深搜索 | 无可靠收益 | 交火短促且不连续 |
| 第一版学习 gate | 安全覆盖 0% | 没有证据不能跳过物理搜索 |
| 第一版学习 Top-7 先验 | p95 无改善 | 离线动作准确不等于产品加速 |
