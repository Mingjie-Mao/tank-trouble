# Tank Trouble AI

把 Flash 游戏 **Tank Trouble** 逐行反编译移植成 Python，然后在这个环境上回答一个问题：

> **AI 能否自主学会击败一个手写游戏 AI——能到什么程度，什么方法最有效？**

对手是原版内置脚本 AI **Laika**（约 980 行，会躲一切子弹，10 帧决策周期）。
它并不弱：Laika 镜像自己打自己，真胜率也只有 **40.2%**——因为在这个游戏里，
先杀死对方不等于赢。

当前部署的智能体是一个**零在线搜索的纯前向网络**，对 Laika 真胜率 **88.7%**，
每次决策 8.6 ms。特权离线搜索老师达到 **99.0%**。

一切可复现：引擎纯 Python 零依赖，无头 6000+ 帧/秒，种子完全确定。

## 怎么做到的

### 1. 无模型 RL 到 36.4% 撞墙

P8 之后连续八个奖励塑形变体全部 NO-GO。真正让数字动起来的两次改动都是
**观测**改动：来袭子弹的弹道预演（+8 点）和最短路导航方向（+3 点）。

> **信息 > 激励 > 容量。** "学不会"大多是"看不见"。

这一阶段还撞出两条硬限制：CNN 地图头惨败于 4 个手工导航特征（P18 = 22.5%）；
微调的**有效窗口约 2M 步**——恒定学习率续训必崩（P16 用 60M 步实证）。

### 2. 决策时搜索零训练直接 96%

一个无未来函数泄漏的沙盒，把全部 18 个动作组合各前推 48 帧，开箱即
**96.0%**。用 P17 网络剪枝到 top-K 再深推，K=12 完全追平全量搜索且快 4.3 倍
（36 ms/决策，实时可用）。

这次重新定义了整个项目：**搜索不是选手**，它是量出"这个游戏有多吃规划"的
*测量仪*，以及产标签的*老师*。

### 3. 蒸馏把搜索装回网络

克隆老师的 argmax 动作会失败（8.9%），原因是**并列陷阱**：多个动作一样好时
argmax 随机选边，于是标签恰好在最关键的状态上自相矛盾。

正确做法是回归**全部 18 个动作的结局评分**——学价值地形，而不是模仿一个动作。
这就是 P21b（62.2%），随后是 DAgger 专家迭代（P22，74.7%）、360° 炮线老师
（P25v2，76.9%）、摊销 MPC（P26，87.1%），最后是把风险/价值头当作
**分数微调而非动作接管**（P27b，88.7%）。

度量脚注：top-1 准确率在这里数学上不可用——标签中位有 14/18 个动作并列，
完美预测器上限只有 11.9%。正确指标是**后悔值**：P21b 有 93.6% 的决策选中够好
的动作，中位后悔为 0。

### 4. 特权老师（99%）

克隆引擎的**完整状态**，包括 RNG 流和 Laika 的隐藏内部变量（20 种子 ×
20000 帧指纹零失配验证），再加上严格拒绝预测死亡/双亡的安全屏蔽。
它是现役标注 oracle，不是能部署的东西。

## 网络

![P21b 评分网络架构](docs/scorenet_arch.svg)

部署冠军由 `p26_amortized_mpc_iter05.pt`（动作评分底座）和
`p27b_risk_value_iter00.pt`（风险/价值头）组成。每帧只做一次前向和确定性动作
重排，不跑 rollout。上图是奠定这一范式的 P21b 前身：*对全部候选动作预测结局，
再做风险校准。*

**408 维输入 = 当前帧的全部物理事实**（只报事实不做判断，无未来信息）：

| 块 | 维数 | 内容 |
|---|---:|---|
| 基础观测 | 125 | 自车 6 · 敌车 8（路径距离/LOS）· 24 射线 · 弹槽 6×6 · 弹道预演 6×4 · 射击扇 7×3 · 导航 4 · 计时/扳机 2 |
| ★ 动作条件预演 | 18 | 9 种走法各推 24 帧 × [会中弹?, 几帧后] |
| 弹槽补全 | 24 | 第 7–10 颗子弹 × 6 |
| 全迷宫位图 | 240 | 12×10 格 × [下墙, 左墙] |
| 卡墙标志 | 1 | 上一帧是否撞墙 |

带 ★ 的那块是蒸馏能不能成的关键：标签问的是"往哪走能活"，输入里就必须存在
动作条件信息，否则网络在结构上根本表示不了这个排序。

**关于尺寸**：1024×3、约 2.5M 参数，只在实验证明容量是瓶颈时才加大。三次对照
说明它从来不是瓶颈（两次观测补全 +11 点；八次奖励变体 0；P21a 大网只 +1%）。
不用 RNN 也不做帧堆叠，因为在公平性规则下老师标签是当前状态的纯函数。

## 测量协议

这两条规则代价最大，在本仓库里不可协商。

1. **先杀 ≠ 赢。** 原版计分下先杀后死 = 双亡不得分。天真的 destroy 口径会**虚高
   15–29 点**。本文所有对外数字一律是真胜率，`evaluate.py` 默认双口径输出。
2. **100 局评估是噪声。** 训练回调的评估有 ±9 点系统偏差，只可看趋势。
   **定级必须 1000+ 局全新种子，换冠军必须第二种子基复验。** P26 suppress-only
   在 40 局里像 90%，300 局塌到 84%。

## 哪些没走通

负结果是这个项目里最可迁移的部分。

| 尝试 | 结果 | 失败原因 |
|---|---|---|
| P8 之后的奖励工程 | 八连 NO-GO | 塑形已饱和；对已收敛策略做单点行为矫正会破坏自平衡 |
| CNN 地图头（P18） | 22.5% | 惨败于 4 个手工导航特征 |
| 60M 步长训（P16） | 36 → 30 → 21% | 恒定 lr 下微调有效窗口只有 ~2M 步 |
| argmax 行为克隆（P19） | 8.9% | 并列陷阱 |
| 学习价值叶子（P23） | 老师 93.5 → 87.5% | 价值泄漏 + on-policy 价值陷阱（把被动固化） |
| 生存课程（P24/v3） | 老师成立，学生 58.7% | 课程分数 ≠ 原版分数；2s 免疫超出老师 48 帧视野 |
| P27 宏动作头 | 72.5% | 接管式动作会打断本来正确的基础策略 |
| P29/P29b/P29c 蒸馏 | 被拒 | 标签语义混杂——h48/h72/h96 平均出"光滑但不决断"的目标 |
| 精确老师蒸馏先导 | 三个候选全被门拒 | 全网络微调破坏冠军的分数校准 |
| **学习价值函数 V(s)** | **六个受控消融，R² 全在 0 附近或为负** | 见下 |
| **更深的搜索** | **h72 vs h36 头对头 41.1% ± 12.9** | 见下 |

最后两行否掉了 AlphaZero 式飞轮的两个主要杠杆，而它们失败的是同一个原因。
价值那条的消融链：自博弈对称结局（击杀 223:243、超时 226:226）方差 0.343
仍只有 R² +0.017；网络 463k → 6k 参数 R² 不动（排除过拟合）；按局内位置分桶，
连最后 5% 帧 R² 也只有 0.109（排除"未来不确定"）；加入击杀场特征后 R² 从
−0.013 掉到 −0.091（排除缺任务特征）。

> **在这个游戏里，局面几乎不决定胜负。** 一局由一次短促的反射性交锋决定，
> 开火瞬间的几何一秒内就完全变了。这和围棋象棋那类"局面强烈决定结局、
> 看得越远越强"的游戏不是一类。

## 已知局限

- **蒸馏鸿沟是主矛盾。** 老师 99% → 网络 88.7%，中间 11 点**不是数据量问题**：
  精确老师的决策依赖 RNG 和 Laika 隐藏状态，而观测里根本不存在这些信息，
  蒸馏在信息上不封闭。
- **行为质量落后于胜率。** 300 局里行为观察器仍计到约 3400 次
  `missed_fire_window` 和 2100 次 `stutter_stall`。单帧无记忆网络无法对一条
  路径做出承诺。
- **双亡仍是残余失败模式主成分**——P27b 官方 3.2% / 4.2%。
- **99% 不可外推。** 它只对固定基准成立，未见种子仍有 3 局明确失败。
  **不能说这个游戏被解决了。**
- **对手只有一个。** 全部训练与评测都对 Laika。这个游戏是否防守占优，必须靠
  两个强手自博弈来裁决，目前还没有。
- **工程债。** `EXPERIMENTS.md` 停在 P25（P26–P30 散落在 `analysis/*.md`）；
  `models/` 不入库，冠军离开本机不可复现；30+ 个一次性 `run_*.sh`。

## 当前路线：exploit 搜索 → 对手建模 → 飞轮

飞轮的两个杠杆都死了之后，现役这条线打的是另一个弱点。搜索的 rollout 里对手
模型写死 `opp_model="L2"`——把所有人都当成 Laika。这正是群友能稳定打赢它的
根因，而修这个不需要价值函数：

```
TAS 式存档回溯搜索
        ↓  枚举出大量能杀死当前模型的时间线
网络建模对手空间（对手 = Laika + 偏差，z 从实战推断）
        ↓  搜索的推演变准 → 搜索变强
旧 exploit 失效 → 再搜
```

每轮的新信息来自**新发现的打法**，不来自任何估计。技术前提是这个游戏确定性：
`(game, teacher)` 一起 pickle 后回溯能逐位复现决策（54 KB / 0.4 ms）。

以 Laika 为参照系而不是从零建模，因为对手模型跑在 rollout **里面**
（一次决策约 90 次对手推理），必须是微秒级；且 `z=0` 时严格等于现状，
遇到没见过的对手最坏退回今天的水平。

**擂台规则**（搜索用，区别于原版计分）：30 秒（750 帧）结算；击杀并存活 = 1.0；
超时按追猎链分裁决（领先 0.4 / 落后 0.2）；双亡 0.1；自己死 0.0。
超时对搜索算失败，要回溯。

```bash
# 地毯式 exploit 搜索（断点续跑，重启自动跳过已完成的图）
caffeinate -i python3 training/exploit_search.py run --maps 64 --workers 8

# 回放搜索出来的击杀路径
python3 training/watch.py --policy exploit-replay

# 新规则擂台
python3 training/watch.py --policy arena --ranked --seed 40000000
```

每条战线的完整计划见
[docs/PROJECT_REVIEW_2026-08-04.md](docs/PROJECT_REVIEW_2026-08-04.md)；
P26–P41 探索线归档在 `docs/P26_*` … `docs/P41_*`。

## 游戏机制速览

25 FPS · 迷宫每局随机（4–12 × 4–10 格）· 子弹每帧 7 子步、撞墙反弹、
250 帧寿命、**可打死自己** · 弹匣 5 发 · 死亡后 125 帧才结算计分，这就是双亡
窗口的来源 · Laika 是会躲一切子弹的目标优先级脚本 AI。

忠实度细节（包括 AS2 的 `undefined == 0`、NaN 传播等怪癖）见
[docs/PORT_NOTES.md](docs/PORT_NOTES.md)。
